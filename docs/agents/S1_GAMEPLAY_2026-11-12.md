  Never copy its code, names, headers, comments or struct layouts into the project (source, tests, docs). Write our own

- **Dead code** only with the three proofs of DEADCODE_2026-11-12.md. One tape with zero hits is NOT proof.
- **Never** deploy to `game/`, push, merge, rebase, or touch gc-removal / agent/opt-integrate. Never edit another worktree.

  `runtime/tests/s1_<field>_*_tests.cpp`, `docs/re/<field>.md`.

## CPU, in rounds (enforced)

S1 budget: 14% of the machine = two slots of 7%. Every heavy command (build, ctest, contract test, benchmark, replay,
profiler, generator) runs as

    powershell -NoProfile -ExecutionPolicy Bypass -File tools/agents/capped_run.ps1 -Command '<cmd>' -CpuPercent 7 -Lock s1-slot-<a|b>

Timing runs add `benchmark`: `-Lock s1-slot-a,benchmark`. Bash: write a script file and pass
`C:\PROGRA~1\Git\bin\bash.exe /h/.../script.sh` (inline quoting gets mangled). The slot mutex makes the agents of a slot take
turns = rounds: hold the lock for one command, not for a whole plan. RE work (reading the decomp, the lifted code in
`.build/watch` generated sources, writing docs) needs no slot; do it while you wait. One build at a time per worktree,
`-m:2`, headless only. Pass `-DSHADOW_DEPLOY_DIR=` and check `grep -c copy_if_different .build/watch/ShadowTheHedgehog.vcxproj`
is 0 before the first build. If tools/platform/regen_manifest.py fails in a fresh worktree, copy `.build/dolrecon` from
H:/ShadowTheHedgehogDiskGC_Extract/wt-opt-integrate/.build/dolrecon. The first full build of a fresh tree takes ~60 min
at 7% and the PDB error C1090 on a full build is known: re-run once (incremental).

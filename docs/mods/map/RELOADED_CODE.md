# What Reloaded's code changes are, and which data depends on them

Generated by `tools/mods/reloaded_code_map.py` (with `tools/mods/reloaded_data_census.py`) from a local copy of
ShdTH-Reloaded v1.2 (no licence: knowledge only; none of its code, assembly or files is in this repository, and the
tables below carry addresses, sizes, counts and our own descriptions only). Data: `test_data/mods/reloaded_features.json`
(the manager's feature list) and `test_data/mods/reloaded_data_census.json`.

## 1. What the code is

Reloaded's gameplay logic lives in three places, all built on the **NTSC-U** executable:

- `ISO EDITS/sys/main.dol`: the NTSC-U DOL, edited by Melee Code Manager (its header carries the stamp of that tool).
- `codes/code/MCM/*.txt`: the assembly library the DOL was built from: 110 entries, 224 patch sites.
- `codes/code/GUPR8P.ini`: 33 optional Gecko codes (preferences, cheats, and codes that restore original behaviour); they are not part of the DOL.

**DOL diff (our measurement).** Same 10 sections and layout as the NTSC-U DOL. 5670 bytes differ: 19 in the header stamp,
4892 inside 0x800034AC to 0x800053E0 (the original DOL's debugger interrupt-vector stubs, zeroed and reused as free space for the mod's code
caves; about 1390 instruction words of injected code are reachable from the hooks) and 759 elsewhere. Of those 759, 0 are not within 64 bytes
of a library patch address: **every change in the DOL is described by the library**; the DOL holds nothing the text files do not list.
Every library entry's "hex to replace" equals the NTSC-U DOL word at its address (None: 4, True: 220).

Patch kinds: branch-to-cave 85, data 70, inline-code 69. "branch-to-cave" replaces one instruction with a jump into the
free-space cave, which runs the new logic, executes the replaced instruction and jumps back. "data" patches rewrite constants in the DOL's data
area (floats, a few strings and table words). They are DOL contents, not files, so a file overlay cannot carry them.

## 2. PAL counterparts

The PC build translates the **PAL** DOL (GUPP8P). Each NTSC-U address was mapped with the repository's verified function-level map
`extract/address-maps/GUPE8P.map` (PAL function bodies and data against NTSC-U, built by `tools/ppcrecomp/disc_map.py`), and where the map
has a gap (functions whose body differs between the regions) by a unique signature search of the surrounding original code. Status:
"exact" = the original word is identical at the PAL address, "shape" = same instruction apart from displacements that move between regions
(small-data offsets, branch targets), "differs" = different. Confidence: high = exact/shape with at least 12 of 13 neighbouring words agreeing
(code) or an identical value (data); medium = shape with a weaker window or a value that differs; low = no PAL place found.
Result: high 220, medium 4 (patch sites); mapped via address-map 222, signature 2. PAL addresses of every patch are in the JSON.

Reloaded's caves read and write NTSC-U small-data and global addresses (flag bytes, pad structures). A PAL version would need those re-derived with
the data deltas of the map (about -0x1060 to -0x10F0 in the data area). Not attempted: no code is being reimplemented here.

## 6. How the manager should use this

For an installed mod whose `codes/` folder holds a modified DOL, MCM library or Gecko ini, list the features of `test_data/mods/reloaded_features.json` with kind `code` or `both`
as "not on this build", show each `effect_without_code`, and the `dependent_data_paths` that are installed but inert. Kind `data` features need no warning.

## 7. Limits

- Function names are not given: the repository has none for most of these functions, and the only NTSC-U symbol map is a third-party file without a licence. The PAL function column is the start address from `extract/functions.csv`.
- The cave code was read (disassembled offline) to find which data it touches, not copied; the JSON carries no instruction words of it. Descriptions are ours, from reading the hooks and the files.
- "Evidence: static" statements come from reading the stock DOL strings and the mod files, not from play. Only the rows marked observed were run on this build.
- Nothing here changes the game or the loader; gameplay stays bit-exact. A later native opt-in implementation of any feature would be a new, separately validated piece of work.

# ShadowRecomp's PC-port features, against ours

**Source and licence.** Notes on ShadowRecomp (FoxWorkshop/ShadowRecomp, GPL-3.0), the Xbox recompilation of the same game, written from a read of its code on 2026-11-16. Mechanisms and data are described in our words; no code was taken, and none should be. Xbox addresses are hints for finding the same code in the GameCube DOL (tools/guest_classes.py for class names).

**What it means for us.**
- **They have 178 config entries and about 38 menu rows.**
- **Already in our port:**
  - controller remapping (`tools/padconfig`, the configurator);
  - button-prompt glyphs;
  - rumble;
  - a portable layout;
  - widescreen and display options;
  - the high frame rate foundation (docs/HIGH_FRAME_RATE.md).
- **Not in our port** (no trace in source or docs):
  - **Achievements:** 17, each detected by a hook at the game function that already knows the fact, with a
    checksummed file.
  - **A mod loader:** SA Mod Manager compatible, replacing loose files and files inside `.one` / `.afs` archives.
  - **Built-in codes/cheats.**
  - **An update check.**
  - **Discord presence.**
- **Ideas for our options menu:**
  - glyphs that follow the last controller used;
  - per-player deadzone and sensitivity;
  - a HUD-width cap for ultrawide;
  - FMV Fit / Fill.

## The notes

Source: /home/user/foxworkshop/shadowrecomp at commit 9fcbc85 (v1.0.0, GPL-3.0). Read-only research. No code is reproduced here. Paths below are relative to `ShadowRecomp/` (the source dir) unless stated.

What it is: a static recompilation of the **original Xbox** `default.xbe` (x86 to C++ via XboxRecomp2) with an SDL3 + plume (D3D12 / Vulkan) host, Dear ImGui for all custom menus, and a patch layer (about 17k lines in `patches/`) hooking guest functions by address. Windows + Linux (Flatpak, Nix, tar.gz, zip). It does **not** accept GameCube or PS2 data (README FAQ).

Reading note on "Where": `config_def.h` = `user/config_def.h`; names in the tables are the TOML key names in `config.toml`.

### 0. Counts

- `config_def.h` defines **178 config entries** in total: 114 written out directly, plus 64 generated by a macro (16 pad buttons x 4 players).
- By section: System 8, Input 20, Bindings (keyboard) 24, Bindings1P-4P 64 (16 each), Audio 8, Video 24, Codes 28, Update 2.
- Visible in the in-game options menu: **about 38 rows**, plus the remap sub-menu (24 keyboard rows, or 16 pad rows plus deadzone and sensitivity, per player), plus Sound Test. Everything else is config-file only or hidden.
- Optional or hidden entries: the 3P/4P variants (camera, vibration, deadzone, sensitivity, 16 pad bindings each = 36 entries) and the 28 "Codes" entries. They are not written to `config.toml` and not shown unless activated (Extended Multiplayer mod for 3P/4P, SA Mod Manager profile for Codes). A hidden entry becomes visible if it is present in the file. The loader reads a key if its section exists. For Codes this only looks viable by hand-editing, which I did not test.
- Localisation: 6 UI languages (English, Japanese, German, French, Spanish, Italian). Every option name and description is localised in all 6.

### 2. Details worth copying as design

#### 2a. Controls UX

- **Xbox-pad abstraction.** The game's input layer is hooked at the XInput-equivalent functions (`sub_4248A6` get state, `sub_424919` set vibration, `sub_2AAC20` open). The host builds a legacy Xbox pad frame (digital bits, 8 analogue button bytes, 4 stick axes). Everything else (remap, deadzone, keyboard) happens before that point, so the game never needs patching per device. This is the main thing to copy if our port has a similar choke point.
- **Per-player bindings.** Each of 4 ports has its own table (SDL gamepad button to Xbox button). Ports follow SDL pad connection order (first free slot). Hot-plug handling is posted to the main thread because opening or closing pads inside the event watcher can deadlock SDL.
- **Keyboard as a virtual pad on a chosen port.** Ctrl+1..4 re-targets the keyboard to port N at runtime. That gives keyboard-plus-controller 2P with no menu. Keyboard stick axes are digital (full deflection), merged on top of any real pad on the same port.
- **Remap UI.** A "Customize Input" row opens pages: Keyboard, Gamepad 1P, Gamepad 2P (3P and 4P only if Extended Multiplayer is active). Press accept on a row to listen:
  - 5 s countdown shown in place of the value, with Esc or timeout to cancel;
  - input already held when the row was selected is ignored;
  - a wait-for-release phase (min 0.25 s) so the capture press does not leak into menu navigation;
  - pad buttons count only at 50% or more press;
  - **duplicate bindings are auto-cleared**: the old holder becomes "---" (unbound), never swapped;
  - Reset (X) on a row restores that row's default and also clears any new duplicate;
  - only scancodes the config can save are accepted for the keyboard.
- **Key labels respect layout.** Keys are saved by physical scancode, but labels come from the OS layout (so AZERTY users see their own letters). A label is used only if the UI font has the glyph. Special keys (Enter, arrows, Ctrl, etc.) are localised strings.
- **Glyphs per controller type.** Prompt icons (A/B/X/Y in the menu guide bar) come from one sprite sheet with three skins: PS2, Xbox and GameCube. `Auto` follows the *last used* controller (SDL gamepad type: Xbox 360 and One map to Xbox, PS3, PS4 and PS5 map to PlayStation, anything else is unknown and falls back to Xbox glyphs). Keyboard and mouse use of the menu does not change the controller skin. The remap page uses text labels (Cross, Circle, Square, Triangle, SHARE, OPTIONS, L1, R1, L2, R2, L3, R3) when the pad is a PlayStation type. Switch, Steam and GameCube types are detected and logged but not used for glyph choice. The button-guide bar is data-driven (icon, label key, alignment, optional visibility flag, optional max width squashing text horizontally for long translations).
- **Stick shaping.** A radial deadzone with proper rescaling plus a gain, applied per player and to both sticks; the output is renormalised so it never exceeds full deflection. Also an explicit clamp to fix an int16 overflow on full "up" (comment in the code).
- **Rumble.** SDL rumble with a timeout, per-player on/off, zeroed on focus loss.
- **Controller LED.** DualShock and DualSense lights track the Chaos power (neutral, hero, villain) or show a player colour, with a brightness slider. SDL's own PS5 player-LED hint is disabled so the game owns the colour. Worth copying for players who own those pads.
- **Cursor and mouse.** Mouse use shows the cursor and counts as a device. Controller input hides it. In fullscreen the cursor stays hidden unless the window grants visibility.
- **No gyro and no touch support.** There is no gyro, no motion aiming and no mouse-look in the source (grep clean). Touchpad is just a bindable button.
- **Multiple controllers / 2P.** 4 ports. 2P is the vanilla versus mode, with P2 able to drive the partner. 3P and 4P come via the multiplayer mod, which also unlocks 3P and 4P rows in the menu.
- **Bonus: remap rows for player 3 and 4 only appear when needed** (optional config entries stay out of the file and the menu until activated). A neat way to keep the options screen short.

**Detection model:** no polling and no engine-wide event bus. Each achievement is a small hook at the exact guest function or code address where the game itself already knows the fact, then it reads guest memory to decide.
- Endings 1 to 10: a hook after the "route / ending" function runs. It reads the current route node, and matches it against the game's 10-entry ending-node table. Two endings share one node, so the mission type (dark vs hero) disambiguates. Only fires in story mode.
- Last Story and Expert Mode: hook on the stage "goal action" teardown. Fires when menu mode and stage id match (Devil Doom in Last Story mode; Last Way in Expert).
- A ranks: hook where the game recomputes its A-rank count. Fires at 71 or more.
- Keys: hook on the per-stage key-count update. The game has no total key counter, so it loops the save's per-stage data (23 stages x 5 keys) and counts non-empty slots. Fires at 115 or more.
- Tank: hook on the tank's "destroyed" callback. Checks stage id (Lethal Highway) and that any of the 4 players is in the vehicle-driving behaviour state.
- Central City time: hook on the mission-complete function. Checks stage id, hero mission, and the stage timer float below 180 s.
- Master achievement: when 16 records exist, the 17th is created automatically.

**Storage:** `ShadowAchievementData.bin` next to the save: a signature, a version, an XOR-based checksum (weak, but it does catch corruption), and 17 fixed records (id and timestamp). Saved immediately on each unlock (not only on exit). If the file fails validation (size, signature, newer version, checksum), the manager records the status and **does not overwrite it for the session** (protects a file from a newer build). The file lives in the mod's redirected save folder if a mod redirects saves (see 2e), otherwise falls back to the base save folder. It loads when the game opens its save (hooks on the save-open functions).

**UI:** pause menu entry opens a scrolling list (4 rows visible, fast-scroll on hold) with icon, name, locked or unlocked description and an unlock date. A toast shows for 5 s on unlock when enabled. README says: "Achievements cannot be used with platforms such as Steam or RetroAchievements" (it is a local system only).

#### 2c. Installer flow and validation

Flow (all drawn in the game's own styled ImGui, pad / keyboard / mouse navigable, with music):
1. Select language (6 buttons; this also sets the game language).
2. Introduction ("you will need an Xbox copy of Shadow the Hedgehog").
3. Select game. Drag and drop or Browse: an **ISO** or `default.xbe` (an extracted folder also works: dropping a folder uses `default.xbe` inside it). A path box shows an ellipsis-truncated tail, a short yellow flash confirms a drop, and a red status line shows errors. Parsing happens in a worker thread with the buttons disabled.
4. Check space: shows required size (from the manifest) and available space on the install target (the first existing parent folder).
5. Installing: progress bar, current file name. About 90% is extraction and about 10% is a second phase "Compiling shaders...", which pre-builds shader and pipeline caches so the first launch does not stutter.
6. Success page (credits) or Failure page with Retry (goes back to Select game).

Validation and safety:
- **Source readers.** Directory reader, or a native **Xbox ISO (XISO) reader** (checks the "MICROSOFT*XBOX*MEDIA" header at the offsets for XGD1, "global" (redump-style) and XGD3 layouts, then falls back to scanning every 64 KiB; depth limit against corrupt-image loops; credits extract-xiso). Case-insensitive path lookup.
- **Manifest of expected files** (about 3,500 entries, generated by a tool called `fshasher`) with a 64-bit **XXH3 hash** per file. Each file lists several acceptable hashes (several known releases). A file matches if its hash equals any one of them. A missing file or a hash mismatch fails with "does not match any known version".
- Files are copied while hashing, in one pass, in disk order (sorted by ISO offset for speed), and `default.xbe` is processed last.
- **Journal and rollback.** Every file and directory created is recorded; on any failure all of it is removed, and empty parent folders are pruned. The previous `default.xbe` is deleted up front so a half install cannot be mistaken for a good one.
- Refuses the source and destination being the same folder.
- Install target is `<exe dir>/game/` (the `game` subfolder), so removal is a folder delete. Portable by default.
- **Re-verification:** `--install-check` re-hashes the installed folder against the same manifest, with percentage output and a dialog. A failure message tells the user to relaunch with `--install`. The wizard auto-runs when `default.xbe` is missing.
- Backend failure at startup shows a localised dialog listing causes (D3D12 or Vulkan, drivers, OS); a memory failure shows "needs 8 GB, page file 4 to 8 GB".
- Updates: **no auto-updater.** README: copy a new release over the old one; saves and settings are kept; no reinstall. The in-game check only offers to open the releases page.

#### 2d. Mod loader file-replacement model

Compatible with **SA Mod Manager** profiles and mod folders (the "Sonic Adventure mod" format), so users manage mods with an existing tool. The loader sits in `<exe dir>/mods/`.

- **Profile.** Reads `mods/.modloader/profiles/profiles.json` (picks the profile by `ProfileIndex`) or `Default.json`. Uses `EnabledMods` (ordered list of folder names) and `EnabledCodes` (list of code key names that flip the hidden Codes config flags). No profile means no mods.
- **Per-mod `mod.ini`.** Name, Author, Description, Version, ModID, `RedirectMainSave`, and a `[Config]` group with `IncludeDirCount` and `IncludeDir0..N`.
- **Layers (higher wins):**
  1. Later mods in the profile beat earlier mods (iterated in reverse).
  2. Within a mod, "include dirs" (the mod's configurable option folders, "codeless config", whose active choice comes from the mod's `config.ini`) beat the mod's root `game/` folder.
  3. Loose files: the mod's `game/` tree mirrors the installed game tree. The resolver normalises the path, hashes it, caches the result per thread, and returns the first existing file. No existing file means the original is used.
- **In-archive replacement (`replace.ini`).** The game packs assets in `.one` archives and in `.afs` audio archives. Rather than forcing mods to repack, a `replace.ini` has one group per archive (extension and case normalised, slash style normalised, wildcards allowed such as `event/*`), with `assetname = path\to\file`. When the archive is opened, the loader patches the asset table entry and size so the game reads the replacement bytes from disk. Priority: include-dir rules beat root rules; an exact archive name beats a wildcard; longer pattern beats shorter.
- **Texture dictionary append.** `texture.txd+=path` (or a folder, or a comma list) merges new textures into an existing TXD (same name replaces, new name is appended) instead of replacing the whole TXD. It parses the RenderWare TXD, requires Xbox-platform textures, and warns if the RW version is not the game's 3.7.0.2. This allows small texture mods that do not conflict.
- **AFS (audio) replacement** for voice and music, matched by entry name, with the voice-language setting deciding which archive applies.
- **Safety.** A replacement file whose path points outside the mod folder is ignored. Start-up logging reports any `replace.ini` entry that matched no archive (a typo check). Errors are logged with mod name, section and key.
- **Colour tweaks.** `colors.ini` with `[SpinTrail]` and `[JumpBall]` per-character RGB, applied by hooking effect creation.
- **Reserved IDs.** `shthr.reloaded` and `shthr.multiplayer` turn on built-in gameplay packages (see Codes).
- **Codes tab.** Because native code mods are impossible in a recompilation, ready-made "codes" are compiled into the exe and toggled by the same SA Mod Manager "Codes" UI. README: code modding is "planned for a future update".
- Mod-supplied files are logged with a "Mod Loader" tag when loaded.

#### 2e. Save file handling and location

- **Location.** Windows `%APPDATA%\ShadowRecomp\`; Linux `~/.config/ShadowRecomp/` (falls back to `~/.ShadowRecomp` if `.config` does not exist). Putting `portable.txt` next to the exe makes everything live in the exe folder. Inside: `config.toml`, `save/Save.dat`, `save/ShadowAchievementData.bin`. The recompiler's own Xbox "U:" partition is faked.
- **How the Xbox save model is bridged.** The game opens `u:\<hex-id-folder>\...` (Xbox title-ID style folders; an all-hex segment, or the word "save", is stripped). Those paths are resolved to the `save/` folder (or a mod's redirected folder). A directory listing of `u:\*` reports a single "save" entry if `Save.dat` exists, so the game's "is there a save?" logic works. `XCreateSaveGame` and the user-path-exists and create-folder functions are stubbed or hooked. Missing-save file opens are not logged as errors.
- **No signature, memory-unit or XCALCSIG logic.** A search found no `XCALCSIG`, memory-unit or signature code. The save is just a plain file the game reads and writes with its own format. No Xbox save signing is emulated, so saves are portable between installs and editable.
- **Prompts.** Game-authentic prompts drive create, overwrite, load, damaged and failed-save messages (localised, replayed through ImGui). `ConfirmationPrompt` can turn the extra ones off to match GameCube behaviour.
- **Mod save redirect.** A mod with `RedirectMainSave=true` points both the save file and the achievement file at `<mod>/save/`, so total-conversion mods do not corrupt the base save. Achievements try the redirected folder first and then fall back to the base folder.
- **Config file.** TOML, loaded at startup, re-written when options change or on exit. Hidden and "optional" entries are not written unless set. A parse error is logged and defaults are used.
- **Updates keep data.** Saves and settings sit outside the install folder.

#### 2f. Accessibility and comfort options

There is no dedicated accessibility menu. The relevant pieces:
- Subtitles on or off (default on); Hints on or off.
- Controller remapping for keyboard and every pad, 4 ports; stick deadzone and sensitivity per player; reverse horizontal camera per player; rumble per player.
- Controller glyph choice (Auto, Xbox, PS2, GameCube) and PlayStation-style text labels in remap.
- Separate volume for music, effects, voices, cutscenes, plus master; mute on focus loss; media-aware music ducking.
- Brightness slider and bloom intensity slider, both with live preview.
- Unlockable frame rate (up to 240) and unlocked cutscene frame rate (option); VSync toggle.
- Wide aspect-ratio and HUD-width cap; FMV Fit or Fill.
- Confirmation prompts toggle (guards against mashing; the title screen also locks B for a moment to avoid an accidental quit).
- Voice language and 6 UI languages, with auto-shrinking text for long strings (button guide, installer fields).
- Not present: colour-blind modes, text-size scaling, hold-vs-toggle options, QTE assists, screen-reader or high-contrast. (Cheat codes like infinite lives are a partial substitute.)

### 3. Known issues and limitations (as stated by the project, plus what the source shows)

Stated in README or FAQ:
- A "Known Issues" section exists but only points to the GitHub issue tracker. No list is shipped in the repository.
- No GameCube or PS2 data accepted (an entirely new recompilation would be needed). Xbox ISO, or an extracted `default.xbe` folder, only.
- Some UI shows visible lines or gaps at high resolutions. This is a vanilla game issue. The advice is to use an "HD GUI" mod. Do not file issues.
- Some sound effects are missing. It is an Xbox-version defect, and a "SFX Restoration" mod fixes it (issue 44).
- Achievements cannot be used with Steam or RetroAchievements.
- Code modding is not yet possible. Only built-in "codes" are available.
- High frame rates: the option warns that glitches may appear above 60 fps (many fixed already).
- macOS is not supported (community contributions welcome). Mobile and touch targets should be forks.
- Builds come only from the GitHub Releases page.
- Minimum specs: Sandy Bridge CPU, a D3D12 FL 12.0 / SM6 or Vulkan 1.2 GPU, Windows 10 1909+ or modern Linux, 2.4 GiB disk. The in-game error text says 8 GB RAM and a 4-8 GB page file.

Seen in the source (my reading, not stated by the project):
- Language, GraphicsAPI, ControllerIcons and VoiceLanguage cannot be changed while a stage is paused; Language and GraphicsAPI also need a relaunch (the app restarts itself with `--quickboot`).
- The "Debug / Codes" category in the options menu is dead code (never unlocked), so codes can only be set through SA Mod Manager (or by editing the config).
- Discord Rich Presence cannot be disabled in the UI or config.
- The update check uses a fixed GitHub URL and `xdg-open` via a shell call on Linux.
- The achievement checksum is a plain XOR, so it is not tamper-resistant. A bad file blocks saving for that session with no on-screen explanation found.
- Saves are not signed or encrypted, so save-sharing and editing are unrestricted.
- Windows-only dark title bar code is commented out. The window icon switching for chaos aura is commented out.
- `patches/limit_break_patches.cpp` is all commented-out experimental code (custom-stage geometry limits). The author notes these would break some stages.
- Gameplay patches that deviate from the Xbox build (GameCube-style enemy target state, etc.) are defaults, with Xbox behaviour under a code toggle.
